# 验证与测试报告

**一句话定位**：这份文档回答"这个仓库里的功能，各自**凭什么**说自己是对的；
哪些结论是本次真实跑出来的，哪些只是早期记录"。适合评审者、接手者，
以及要判断"能不能上真实硬件"的人。

## 一、为什么需要这份报告

**"测试通过"不等于"可以在真实硬件上用"**，这是整份报告的前提。原因是三层错配：

1. **假接口只能证明"实现与假设一致"**。单元测试里的 `FakeLinuxIo` 会按我们**以为**的方式
   应答 `ioctl`；如果内核真实行为与假设不同，测试和实现会一起错，而且错得很一致。
2. **进程测试跑在虚拟机上**。回环网络、临时目录、`mock` 传感器都成立，
   但真实 I2C 的时序、GPIO 的电气特性、PWM 的安全值根本不在测试范围内。
3. **动态检查工具只在执行到的路径上报告**。没有报告不等于没有错误。
   更重要的是，这些工具的结果**会随环境、编译器版本和时间变化**，
   所以必须写清"哪一次跑的、跑的是哪个修订版"。

因此本报告的作用不是宣布"全部通过"，而是把每个功能与**具体证据**对应起来，
并显式区分「本次实测」与「历史记录」。

## 二、设计思路

### 1. 三层测试各自能验证什么

- **单元测试（用假接口驱动）**
  - 做法：`FakeLinuxIo`、`FakeSocketIo`、`HealthLogger` 等替身替换系统调用与日志。
  - 能验证：分支与边界、错误路径、计数与阈值语义、协议解析。
  - 不能验证：真实系统调用与内核语义、线程/进程编排、电气行为。
- **进程测试（启动真实程序）**
  - 做法：Python 脚本启动真实 `bmc-lite`，通过端口、文件与退出码观察。
  - 能验证：生命周期、`epoll`/信号接线、TLS 握手、退出码、SEL 落盘。
  - 不能验证：每个分支（太慢、覆盖太少），以及真实硬件。
- **动态检查（用工具重跑已有用例）**
  - 做法：ASan/UBSan、TSan、Valgrind 各跑一遍已有用例或压力程序。
  - 能验证：内存越界、未定义行为、数据竞争、泄漏。
  - 不能验证：功能是否正确——它们只报"这类缺陷"。

它们**不可互相替代**：只有单元测试能便宜地覆盖"1 万个传感器消失"、
"`/dev/full` 写入失败"这类分支；只有进程测试能发现"停机顺序写反了导致任务被 `rejected`"
这种编排缺陷；只有动态工具能发现"断言全对、但存在数据竞争"的问题。

**术语说明（第一次出现）**：

- **ASan / UBSan / TSan**：编译器提供的运行时检查工具。ASan 查内存越界、释放后使用等内存错误；
  UBSan 查未定义行为（例如有符号整数溢出）；TSan 查多线程数据竞争。
  三者的插桩方式互斥，必须分别构建。
- **Valgrind**：另一套动态分析工具，主要查内存错误与泄漏（退出时应 0 bytes / 0 blocks）。

### 2. 为什么要有"逐字对拍"

只读服务面（`/healthz`、`/metrics`、Redfish 资源）有一个**独立的第二实现**：
`tools/bmc_manage.py`。`tools/gen_service_vectors.py` 把它的响应固化成
`tests/service_vectors.hpp` 里的黄金向量，`tests/core_test.cpp` 再断言 C++ 输出与向量
**逐字相同**（逐字对拍：两份独立实现比输出，不允许"内容等价"）。

动机很直接：**如果期望值由我们自己手填，那只是把自己的假设再写一遍**。
它能发现"代码写错了"，但发现不了"我们对协议的理解本身就错了"。
参考实现是另一份用不同语言独立写出的代码，两者输出一致才说明协议行为已被固定下来；
而且以后任何一方改动导致输出漂移，都会被这条断言立刻抓住。

## 三、具体实现

### 1. 测试构成

构建配置：`CMAKE_BUILD_TYPE=Debug`、`BUILD_TESTING=ON`、`BMC_TLS=ON`。
`BMC_TLS=ON` 会额外注册两个 TLS 变体用例（`peer_tls_runtime`、`control_tls_runtime`）。

| 目标 / 用例 | 数量 | 内容 |
|---|---|---|
| `bmc_tests`（GoogleTest） | 132 | 见下方的文件分布 |
| `bmc_stress` / `scheduler_stress` | 1 | 并发生产者下的队列与总线计数守恒 |
| Python 运行时用例 | 10 | 8 个 + 2 个 TLS 变体；启动真实二进制 |
| **合计** | **143** | |

按 `CMakeLists.txt`，`BMC_TLS=OFF` 时只注册 8 个 Python 用例，即 141 个；
本次为 `BMC_TLS=ON` 的 143 个。旧文档里的 132/134/123 等总数来自早期修订版，
与本次的计数口径不同，不能直接比较。

`bmc_tests` 的 132 个用例分布在 6 个文件：

- `tests/core_test.cpp`：主体用例（Engine、Config、Calibration、芯片解码、注入式 I/O、
  Device、EventBus、Rules、Recovery、Sel、Logger、Worker、Cli、SocketIo、
  HttpParser、RateLimiter、只读服务逐字对拍）。
- `tests/runtime_management_test.cpp`：日志/SEL 降级上报、5 秒节流、不反写日志、状态裁剪。
- `tests/network_test.cpp`：`HttpConnection` 部分写、绝对期限、解析失败回 400。
- `tests/control_test.cpp`：令牌文件权限与符号链接、常量时间比较、严格解析、审计失败可见。
- `tests/uplink_test.cpp`：有界队列丢最旧、退避、在途上限、断线检测、超长事件拒绝。
- `tests/peer_test.cpp`：心跳鉴权、陈旧与恢复只报一次、部分写、期限、明文远端拒绝。

Python 用例逐个说明：

| 用例 | 覆盖 |
|---|---|
| `network_runtime` | 只读 HTTP 回环集成；慢客户端不拖慢采样 |
| `runtime_reload` | SIGHUP 热加载、非法配置被拒、正常停机 |
| `control_runtime` | 控制面 HTTP；动作写入临时文件 |
| `control_tls_runtime` | 同上前提下走 HTTPS |
| `peer_runtime` | 双实例交换代次；心跳不写 PWM |
| `peer_tls_runtime` | 同上，走 TLS |
| `uplink_runtime` | 采集端卡住/重连不拖住采样 |
| `degradation_runtime` | 日志降级可见、5 秒节流、退出码 1 |
| `metrics_export` | `bmc_manage.py` 的指标文本 |
| `fault_injection` | 读失败迁移、坏配置、`/dev/full`、SEL 路径非法 |

### 2. 功能与验证证据对照表

- **单一实现、Linux I/O 注入**：分离源文件、`LinuxIo`/`SocketIo`、C++ Fake。
  验证：`core_test.cpp`、`network/control/uplink/peer_test.cpp`。
- **GPIO character-device**：GPIO v2 请求、线值、失败、`CLOEXEC`、RAII。
  验证：`FakeIo.GpioLineValuesFailureAndDescriptorLifetime`。
- **采样/规则/恢复闭环**：Monitor → rules → Worker → Recovery → Action → SEL/Bus。
  验证：C++ 领域与编排用例、Linux 进程测试。
- **有界线程调度**：有界队列、优先级、并发、排空、统计。
  验证：`scheduler_stress`（本次实测）；TSan/Valgrind（历史记录）。
- **SEL 加固**：常驻 fd、批量写、`fdatasync`、尾部修复、压缩后切换 fd、短写后缀重试。
  验证：`Sel.*`；反复压缩后从磁盘逐次读取。
- **只读管理面**：独立 epoll、64 连接、绝对期限、增量读与部分写、默认关闭。
  验证：`HttpConnection.*`、`network_runtime`、Python 响应向量。
- **控制面**：独立 8 连接、文件令牌、认证/限流、重要审计、Worker/Recovery、可选 TLS。
  验证：`Control.*`、`control_runtime`、`control_tls_runtime`。
- **网络指标**：活跃/拒绝/请求/字节、认证失败/限流、固定角色与有限标签。
  验证：`network_runtime` 的解析、超时与 65 连接验证。
- **上行遥测**：`EventBus` → 有界丢最旧 → 非阻塞重连、指标。
  验证：`Uplink.*`、`uplink_runtime`。
- **实例心跳**：独立端口与令牌、双向代次、陈旧/恢复、CA 与主机名校验。
  验证：`PeerHeartbeat.*`、`peer_runtime`、`peer_tls_runtime`。
- **日志运行中降级**：SEL/总线只报计数变化、5 秒节流、不递归写失败日志。
  验证：`RuntimeManagement.*`、`degradation_runtime`。
- **规则状态生命周期**：按当前传感器裁剪，热加载保留有效确认状态。
  验证：1 万个消失传感器用例、`runtime_reload`。
- **恢复状态内存**：最多 4096 条，到期回收；不淘汰运行中/冷却中的保护状态。
  验证：`Recovery.DisappearingSensorsHaveBoundedCooldownState` 等。
- **芯片寄存器依据**：无章节证据的事实明确标为未核实。
  验证：[芯片驱动与标定](芯片驱动与标定.md) 与源码注释，不推测硬件参数。
- **安装与发布**：从 clone 到安装、systemd、热加载、网络、查询与升级。
  验证：`README`、`package-release.sh`（发布包验证为历史记录）。

## 五、复现命令

本次实测使用的两条命令：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON -DBMC_TLS=ON
cmake --build build --parallel 2 && ctest --test-dir build --output-on-failure
```

下列命令来自 `tools/validate.sh`，本次**没有**重跑，仅作为后续验证的入口：

```sh
bash tools/validate.sh sanitize   # ASan/UBSan，需要独立构建目录
BMC_TSAN_NO_ASLR=1 bash tools/validate.sh tsan   # 规避 GCC TSan 映射问题
bash tools/validate.sh valgrind   # 需要系统装有 valgrind，缺了会以 3 退出
bash tools/validate.sh stress     # 只重复 stress 标签用例 20 次
bash tools/bench-writes.sh 50000  # 写入路径基准
```

GCC 的 TSan 在默认地址映射下无法初始化，`BMC_TSAN_NO_ASLR=1` 会让构建与测试在
`setarch -R` 下运行以关闭本次地址随机化。该选项只作用于测试进程，部署不需要关闭 ASLR。

## 六、优缺点与适用性

**优点**

- **反馈快、范围广**：132 个单元用例把绝大部分分支与边界固定在秒级内跑完。
- **硬件分支可测**：注入层让 I2C 解码、能力位拒绝、GPIO 线值、PWM 写失败都能在不插硬件的机器上覆盖。
- **编排契约被固定**：进程用例断言的是退出码、SEL 文本与 stderr 内容这类可观测契约，
  而不是内部实现细节，因此重构时不会误报。
- **协议漂移会被抓住**：逐字对拍让只读服务面的输出一旦变化就立刻失败。
- **证据分层清晰**：本报告区分实测与历史，避免"很久以前跑过一次"被当成"现在也是好的"。

**边界（这些结论不能从本报告推出）**

- **真实 I2C/GPIO 电气行为必须在目标设备上验证**：时序、上拉、噪声、器件实际量程
  都不在覆盖范围内；虚拟机测试不能替代。
- **哪些指标未经核实**：
  - ASan/UBSan、TSan、Valgrind 的结果本次未重跑；
  - 写入基准的耗时与 syscall 计数、Release 压缩包的集成结果均为历史记录；
  - 芯片常量中，EMC2103 的常数、故障码、内部分辨率与默认 RANGE，以及 ADM1275 的
    命令缺失判断，都没有与发布版手册逐项核对，代码注释里同样标注为「未核实」；
  - 真实硬件的测量精度与 PWM 安全值未经核实。
- **测试耗时不可跨机器照搬**：`27.35 sec` 依赖机器性能、`--parallel 2`
  与临时目录所在文件系统。
- **未纳入范围**：完整 Redfish/RMCP+、DSL、选主/fencing、固件升级。
  BMC-Lite 不是完整 BMC 固件，也不以这些方向代替已实现的功能。
- **已经写明的功能边界**：心跳无选主/fencing；上行无 ACK 与断线重放；
  SEL 无 CRC 与断电事务保证；已提交任务不支持强制取消。这些边界不以测试通过替代。
