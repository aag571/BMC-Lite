# 集成状态与运行限制

采样通过 Device 进入阈值状态机。状态迁移写入日志及 SEL，直接评估规则，同时向事件总线发送异步通知。规则产生恢复请求后提交 Worker。任务复制传感器 ID、动作名称及路径，不引用可能被热加载销毁的传感器对象。恢复结果写入日志、SEL 和事件总线。退出先排空 Worker，再停止总线，最后销毁存储。

日志使用常驻描述符并批量合并写入（默认每 4096 字节落盘一次），不再每条记录一次系统调用。日志默认只 write 不 fsync：它是审计轨迹而非恢复依据，允许崩溃时丢掉最后一批；把 `Logger` 构造参数 `sync` 设为 true 即可恢复"每条记录立即落盘并 fsync"的旧行为。轮转只在"当前文件 + 未落盘缓冲区 + 新记录"确实超过上限时才发生，且轮转前会先把缓冲区写进即将改名的分片以免丢行；无法查询大小的目标（管道、设备节点）跳过轮转判断但仍尝试写入，使写入失败仍可被观测。日志写入失败计数而不终止服务（旧行为是退出）。

恢复只允许 increase_fan 和 inspect_device。前者需要 --enable-actions 才写 PWM，后者仅确认检查请求。规则按每次采样快照确认，状态迁移才写入故障 SEL；通配规则按传感器独立计数。恢复冷却状态最多 4096 个，到期可回收，不淘汰仍运行或冷却中的状态。

SIGHUP 重载规则采用**合并**而不是整体替换：规则 id 与触发状态都没变时，保留该规则在每个传感器上的确认计数与 active 标志；已消失的传感器、被删除的规则、以及触发状态被改写的规则，其状态一律丢弃。因此重载不会把已激活规则复位、也不会重复触发一次恢复动作。传感器与规则都会在改动任何状态之前完成校验，重载失败时两者都保持原样。

daemon 只读 HTTP 默认关闭，独立 epoll 线程、64 连接、5 秒读写期限；控制与心跳各有独立端口和 8 连接限制。网络读取加锁 SEL/配置快照，不能触碰采样对象。Python 管理工具仍是独立只读实现，不能与 daemon 占同一端口。基础资源保持逐字对拍，daemon 指标追加网络计数。没有完整标准 Redfish/IPMI。

SEL 通过常驻描述符追加写入，内存与文件同时只保留最近 max_records 条（超出时重写文件，避免重启后把已淘汰记录读回来）。写入按批次合并：状态迁移与恢复这类关键证据立即 write+fdatasync，普通记录累积到 4096 字节再落盘。启动时若发现尾部残缺记录，默认从残缺行的起点截断并记录丢弃字节数（`Truncate::refuse` 可选择只追加不修改文件）。

SEL 写入失败不再终止服务：失败次数、未落盘字节数与被丢弃字节数会通过 `logger.action`、SEL 自身记录与事件总线各上报一次，未落盘缓冲区上限 1 MiB，超过后丢弃最旧内容并计数。`fdatasync` 失败单独计数（设备节点等不支持同步的路径会持续失败），因为它不代表数据丢失。

压缩 SEL 使用唯一临时文件、同步、rename 并接管新 fd，清除已包含在快照中的 pending；日志和 SEL 在短写后只重试未写后缀。没有 CRC 或断电事务保证，也不协调多个文件写者。恢复锁只保护策略状态，执行动作时释放锁，不同传感器可按并发上限执行。任务不支持强制取消，Worker stop 不支持任务内部调用。完整功能与验证范围见 completion.md。
